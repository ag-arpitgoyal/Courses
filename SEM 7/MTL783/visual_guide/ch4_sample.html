Chapter 4 — Decidability

Which questions about machines can an algorithm always answer, and which can it never answer?

Overview

4.1 Decidable languages

The theme: DFAs and CFGs are finite objects. Any question about them that can be turned into "search a finite thing" is decidable. Whenever the obvious search is infinite, find a way to make it finite.

Thm 4.1 – 4.3 · ADFA, ANFA, AREX: in full version (story: "just run it", then "convert, then run it").
Theorem 4.4

\(E_{\mathrm{DFA}}\) is decidable

Decidable
\(E_{\mathrm{DFA}} = \{\langle A\rangle \mid A \text{ is a DFA and } L(A) = \emptyset\}\) is a decidable language.
The story
"Spill paint on the start state and let it flow along the arrows. Does any double circle get wet?"
A DFA accepts some string exactly when an accept state can be reached from the start state by following arrows. Trying strings one by one never ends, but the DFA has only finitely many states, so the paint has to stop spreading.
Visual: the marking algorithm (each round = paint spreads one arrow further)
Write this in the exam
T = "On input ⟨A⟩, where A is a DFA: 1. Mark the start state of A. 2. Repeat until no new states get marked: 3. Mark any state that has a transition coming into it from any state that is already marked. 4. If no accept state is marked, accept; otherwise, reject."
Why it halts: each round marks at least one new state or stops, and there are only \(|Q|\) states, so there are at most \(|Q|\) rounds.
Why it's correct: marked = reachable from \(q_0\). \(L(A)\neq\emptyset\) ⇔ some accept state is reachable.
The detail people blank on Look at which way the answer goes. \(E_{\mathrm{DFA}}\) asks "is the language empty?", so no accept state marked means T accepts. It's easy to write it backwards under exam pressure.
Trap "Try every string \(w\) and run \(A\) on it" is not a decider: if \(L(A)=\emptyset\) it never stops. The point of the proof is to replace an infinite search over strings with a finite search over states. (Alternative that also works: only test strings of length \(< |Q|\), by the pumping idea. That's still finite.)
Used later: Thm 4.5 EQDFA calls T as a subroutine · Thm 4.8 ECFG is the same "paint" idea on variables · in Ch 5, \(E_{\mathrm{TM}}\) is undecidable because a TM's configurations are not finite.
Rebuild it yourself
Why can't we use the same algorithm for \(E_{\mathrm{TM}}\)?

Marking works because the state graph of a DFA is finite and the state alone determines the future. A TM's future depends on the whole tape, and there are infinitely many configurations, so there is no finite graph to paint.

What does T output on a DFA whose start state is itself an accept state?

Step 1 already marks an accept state, so \(\varepsilon\in L(A)\), the language is non-empty, and T rejects.

4.2 Undecidability

The theme: self-reference. A machine that can be fed its own description can be made to contradict any claimed predictor. In the book, the warm-up (ℝ is uncountable) and the main event (\(A_{\mathrm{TM}}\)) are the same table trick.

Universal TM U, Def 4.12 – Cor 4.18: in full version (visuals: the ℚ zig-zag of Fig 4.16 and the ℝ diagonal of Thm 4.17).
Theorem 4.11

\(A_{\mathrm{TM}}\) is undecidable

Undecidable
\(A_{\mathrm{TM}} = \{\langle M, w\rangle \mid M \text{ is a TM and } M \text{ accepts } w\}\) is undecidable.
(It is recognizable: the universal TM \(U\) just simulates \(M\) on \(w\). The problem is that \(U\) loops when \(M\) loops.)
The story
"The contrarian: ask the oracle what you'd do on yourself, then do the opposite."
Suppose someone hands you a perfect oracle \(H\) that always says correctly whether \(M\) accepts \(w\). You build a stubborn program \(D\): given \(\langle M\rangle\), it asks \(H\) "does \(M\) accept its own description?" and does the opposite. Then you feed \(D\) its own code. Whatever \(H\) predicts, \(D\) does the other thing. So \(H\) can't exist.
Visual: Sipser Figures 4.19 → 4.20 → 4.21. Rows = machines, columns = descriptions fed as input
Write this in the exam
  1. Assume for contradiction that \(H\) decides \(A_{\mathrm{TM}}\): \(H(\langle M,w\rangle)\) = accept if \(M\) accepts \(w\), reject otherwise.
  2. Build \(D\) = "On input \(\langle M\rangle\): run \(H\) on \(\langle M, \langle M\rangle\rangle\); output the opposite."
  3. So \(D(\langle M\rangle)\) accepts ⇔ \(M\) does not accept \(\langle M\rangle\).
  4. Put \(M = D\): \(D\) accepts \(\langle D\rangle\) ⇔ \(D\) does not accept \(\langle D\rangle\). Contradiction, so \(H\) does not exist.
The detail people blank on Why does \(D\) always halt? Because \(H\) is assumed to be a decider, so it always halts, and \(D\) only flips its answer. That's exactly why the trick fails for the recognizer \(U\): if \(U\) loops, there's no answer to flip.
Where is the "diagonal"? \(D\)'s row is the flipped diagonal of the table, so \(D\) differs from every \(M_i\) at cell \((i,i)\). Since \(D\) must itself be some row, it disagrees with itself at its own diagonal cell.
Trap Don't write "run \(M\) on \(\langle M\rangle\) and do the opposite". That's simulation, and it may loop. \(D\) must call the hypothetical decider \(H\), never simulate \(M\) directly.
Same trick as: Thm 4.17 (ℝ uncountable), where the digit flip on the diagonal is the accept/reject flip here. Root of everything in Ch 5: every undecidability proof there reduces from \(A_{\mathrm{TM}}\).
Rebuild it yourself
What exactly does \(D\) feed to \(H\)?

The pair \(\langle M, \langle M\rangle\rangle\): the machine together with its own description as input.

Why does the proof show undecidable but not unrecognizable?

The contradiction needs \(H\) to halt on every input. Recognizers may loop, and the universal TM \(U\) really does recognize \(A_{\mathrm{TM}}\).

Fill in: \(D\) rejects \(\langle D\rangle\) exactly when ____.

\(D\) accepts \(\langle D\rangle\). That's the final line of Sipser's three-line summary.

Theorem 4.22

Decidable ⇔ Turing-recognizable and co-Turing-recognizable

A language \(A\) is decidable iff both \(A\) and \(\overline{A}\) are Turing-recognizable.
The story
"Two horses, one race: exactly one of them is guaranteed to finish."
\(M_1\) shouts "YES" if \(w\in A\); \(M_2\) shouts "YES" if \(w\notin A\). Each may run forever when the answer isn't theirs. Every \(w\) is either in \(A\) or in \(\overline{A}\), so one of them will shout. Watch both, one step at a time, and wait for the shout.
Visual: M alternates one step of M₁, one step of M₂

M₂ (recognizes Ā)

waiting
Write this in the exam (⇒) Decidable ⇒ recognizable. Decidable languages are closed under complement (swap accept/reject), so \(\overline{A}\) is decidable, hence recognizable.
(⇐) Let \(M_1\) recognize \(A\) and \(M_2\) recognize \(\overline{A}\).
M = "On input w: 1. Run both M₁ and M₂ on input w in parallel. 2. If M₁ accepts, accept; if M₂ accepts, reject."
Every \(w\) is in \(A\) or \(\overline{A}\), so \(M_1\) or \(M_2\) accepts it, and \(M\) always halts. It accepts exactly \(A\). So \(M\) decides \(A\).
The detail people blank on Why "in parallel" and not "run \(M_1\), then \(M_2\)"? If \(w\notin A\), \(M_1\) might loop forever, and you'd never get to \(M_2\). Alternating single steps (two tapes, take turns) means a loop in one machine can't block the other.
Trap Don't say "if \(M_1\) rejects, reject". \(M_1\) is only a recognizer, so on \(w\notin A\) it may loop rather than reject. The decider stops only on an accept from one of the two machines.
Immediate payoff: Cor 4.23: \(A_{\mathrm{TM}}\) is recognizable but undecidable, so \(\overline{A_{\mathrm{TM}}}\) can't be recognizable (otherwise this theorem would make \(A_{\mathrm{TM}}\) decidable). This is the key tool for "not recognizable" proofs in Ch 5.
Rebuild it yourself
Can both M₁ and M₂ accept the same w?

No. \(M_1\) accepts only strings in \(A\), and \(M_2\) only strings in \(\overline{A}\). These sets are disjoint, so exactly one accepts.

Using this theorem: a language L is undecidable. What can you conclude about L and \(\overline{L}\)?

At least one of \(L\), \(\overline{L}\) is not Turing-recognizable.
